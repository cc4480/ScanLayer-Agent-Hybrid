# windows-system-info

Three read-only checks on the Windows PC this harness runs on, from one PowerShell script that prints ONE line of JSON. They replace the AlterEgo bridge tools `system_info`, `active_window` and `idle_seconds`.

| Need | Flag | JSON key |
|---|---|---|
| Machine facts (was `system_info`) | `-Info system` | `system` |
| Foreground window (was `active_window`) | `-Info window` | `window` |
| Seconds since last input (was `idle_seconds`) | `-Info idle` | `idle` |
| All three | `-Info all` (default) | all of the above |

## Run it

With the `pwsh` tool, exactly this line (the path contains a space, so keep the quotes and the leading `&`):

```
& "C:\Users\Cho-zen\OneDrive\Desktop\Deepseek super\skills\windows-system-info\windows-system-info.ps1" -Info idle
```

Swap `idle` for `system`, `window` or `all`. A call takes about 1 to 3 seconds; ask only for the part you need, and call it again later rather than in a tight loop.

Windows PowerShell 5.1 works too: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<same path>" -Info idle` (the bypass applies to that one process only). Prefer `pwsh`.

With `-Info idle` only `ok`, `generated_at` and `idle` are present, and likewise for the other values.

- `ok` is `false` when a part failed; the failed value is `null` or missing, and `warnings` lists the reasons.
- Sizes are in GB of 1024^3 bytes, as Windows shows them. `disks` lists fixed drives only. `node` and `powershell.pwsh` are `null` when not installed.
- `window.available` is `false` (with a `reason`) when nothing has focus, for example on a locked screen. `process_name` has no `.exe`. `rect` is in screen pixels and can be negative on multi-monitor setups; a minimized window reports a far off-screen position (about -32000).
- `idle.idle_seconds` counts from the last keyboard or mouse input in the user's session.

## Reading the result

- A small `idle_seconds` (under about a minute) means someone is at the keyboard or mouse. A large one means no input, which can still mean the user is watching a video or reading.
- Input generated by automation (mouse or keyboard tools, scripts) also resets the idle counter, so treat idle as unreliable right after any such action.
- The window is a snapshot of this moment. For "what has the user been doing" you only know the current foreground app; do not claim more.

## Privacy

- A window TITLE can contain private text: email subjects, document or chat names, URLs, file paths, account names. Fetch the window only when the question needs it, and report only what is relevant, usually the application (`process_name`) rather than the title. Do not copy titles into tickets, commit messages, notes or memory, and do not pass them to other people or services unless the user asked.
- Treat the computer name and user name the same way: share them only when relevant.
- The script is read-only. It takes no screenshots, reads no window contents, and does not list other windows or processes. Do not extend it to do so without the user's say-so.
