# QNX Agent

**An AI security agent for QNX 8.0 that can only touch what it is allowed to, proves every action it took, and has its findings re-checked by a second agent before anyone sees them.**

Built for **QNX 8.0** (QNX Software Development Platform 8.0, `qcc` toolchain), target **QEMU x86_64**.

> **Status, stated plainly.** Every component runs and is tested today against a **Linux stand-in target**: a POSIX box standing where the QEMU guest will be. The QNX 8.0 build (SDP install, image, boot, on-target receipts) is Phase 0 and **has not run yet**. Nothing in this repository claims a QNX run until `docs/receipts/qnx-*.md` exists. The on-target pieces are written for QNX first: portable POSIX C, POSIX `sh` + `awk`, `pidin`, io-sock's BSD `netstat`/`ifconfig`/`sysctl`, `slog2info`, `use -i`, and Qnet `/net/<node>` paths. They fall back to Linux equivalents only so the stand-in can run them.

The operator interface is the DeepSeek Harness itself: the `dsh-qnx` bundle around this engine adds the QNX pages to the harness sidebar (see `../README.md`).

## What it does

A model connected over MCP sees **two tools**: `search` and `execute`. It doesn't see the target's 1,500 executables or their schemas.

- **`search`** finds tools on the target by intent and returns typed stubs, such as `netstat(args?: string[]) -> {exit, stdout, …}`.
- **`execute`** runs a short program the model writes. The program calls those stubs and runs in a sandbox with no network, files, `require` or `eval`. Only its return value comes back, capped at 40,000 characters.

Every tool call passes one **gate** before anything reaches the target:

| Step | What it checks | On failure |
|---|---|---|
| 1 | The tool exists in the target's real inventory | `unknown_tool` |
| 2 | The tool is not destructive. `slay`, `kill`, `shutdown`, drivers, shells and anything unclassified are **off by default**, because this is a safety-critical OS | `destructive_off` |
| 3–5 | Arguments are well-formed and pass per-tool rules (`find -delete`, `nc -l`, `sysctl x=1`, `ifconfig … down` are refused), and they don't touch the gateway's own secrets | `arg_rule`, `protected_path` |
| 6 | **Scope:** every target named in argv (IPv4, CIDR, IPv6, URL, `user@host`, hostname, and QNX Qnet `/net/<node>/…` or `on -n <node>`) is the target itself or covered by an operator-signed engagement | `out_of_scope` |
| 7 | The on-target **runner** re-checks its own allowlist and runs argv directly, never through a shell | `runner_denied` |

Steps 1–6 happen before a byte reaches the target. A denial spawns nothing and sends no packet. We prove that with a packet capture, not an assertion (see below).

Every call, denial, run, report and verdict is one line in a **hash-chained audit log**. Edit one byte anywhere and `verify-chain` names the line.

On top of the gate sit **five native checks** that compare the running target with its image manifest: undeclared listeners, world-writable paths and `/dev` resource managers, component checksum drift (with QNX `use -i` build info), network posture, and undeclared processes. Every finding cites the receipt of the call that proves it.

Then the **verification loop** runs. Findings become claims on a board. A second seat, *Agent Smith*, runs in its own process with its own token and reproduces each claim on the target itself:

- **CONFIRMED** when its fresh run shows what the claim says.
- **REFUTED** when the fresh run contradicts it.
- **UNPROVEN** when it can't reproduce the claim, or the claim cites receipts that don't exist.

Only confirmed findings reach the ed25519-signed verified report.

## Proof, measured (Linux stand-in, 2026-11-25)

All from [`docs/receipts/standin-2026-11-25.md`](docs/receipts/standin-2026-11-25.md), generated by `scripts/prove.js`:

- **Ladder:** no token → HTTP 401. `tools/list` → exactly `["search","execute"]`. `search` finds the real `netstat`, and `execute` runs it on the target and returns a receipt.
- **Zero packets.** `ping 192.0.2.77` with no engagement was denied pre-spawn: **0 processes spawned** (target-side spawn log) and **0 packets** (`tcpdump -i any host 192.0.2.77`, running throughout). After an operator signed an engagement, the identical call spawned 1 process and the witness saw 3 packets. That positive control shows the witness was listening. Revoking the engagement brought back the denial.
- **Sandbox.** Every one of these was refused: `fetch`, `require`, `process`, `eval`, `new Function`, constructor-chain escape, dynamic `import`, computed tool names, destructive tools, `find -delete`. An infinite loop was killed at the wall clock, and a 100,000-char return was truncated with a note. On Linux the sandbox process also runs in an empty network namespace.
- **Checks.** On a target with four planted faults (rogue listener on `0.0.0.0:4444`, rogue `telemetryd`, world-writable `/etc` config, tampered component), all four were found, each with a receipt.
- **Verification.** All 5 real findings came back CONFIRMED. The planted false claims came back REFUTED (phantom listener, phantom process) or UNPROVEN (forged receipt, out-of-scope reproduction), and none reached the verified report.
- **Token surface (cl100k_base, a relative proxy):** 349 tokens for `search` + `execute`, against 3,210 tokens to list just the 57 callable utilities as classic MCP tools.
- **Interop.** The official MCP TypeScript SDK client (`StreamableHTTPClientTransport`) connects, lists, searches and executes.
- **Tests.** `pnpm test` (from `src/dsh-qnx`) runs 19 tests: unit tests (scope, engagements, catalog, argument rules, audit tamper) and hermetic end-to-end tests (real runner, real gateway, QNX-format fixtures).

## Layout

```
node-runtime/   qnx-runner.c       on-target runner: argv only, timeout, 40k cap, token, allowlist, spawn log (POSIX C; qcc or cc)
                inventory-qnx.sh   on-target inventory -> catalog.json (POSIX sh + awk; pidin, io-sock formats)
gateway/        server.js          MCP Streamable HTTP (search + execute) and operator API; the harness bundle calls it in-process
                lib/gate.js        the gate: classification, arg rules, protected paths, scope, runner
                lib/scope.js       target extraction (incl. Qnet), engagements (HMAC-signed), CIDR rules
                lib/sandbox*.js    per-run confined child: permission model, no codegen, netns, limits
                lib/audit.js       hash chain, verifyChain, ed25519 seal
                lib/board.js       verification board: claim locks, seat separation, verdict rules
                cli.js             init seats, sign/revoke engagements, verify chain/report, runner allowlist
checks/         5 native checks, run as ordinary execute programs
loop/smith.js   Agent Smith: the independent verifier seat
image/          [SDP] image build, QEMU run with port forward, on-target start, draft QNX manifest
scripts/        standin-up.sh, prove.js (receipts), phase0.sh ([SDP] runbook), fault planting
test/           unit + end-to-end + fake-QNX fixtures
docs/           architecture & threat model, demo script, receipts, submission checklist
```

## Run it (stand-in, about one minute)

Requirements: Linux, Node ≥ 22, a C compiler, `make`. `tcpdump` is only needed for the zero-packets proof.

```sh
cd src/dsh-qnx
pnpm test                             # builds the runner, runs the 19 engine tests
sh engine/scripts/standin-up.sh       # headless: runner on :7781, engine MCP on :8095 (Ctrl-C stops both)
# for the interface, run the harness with this bundle instead (see ../README.md)
```

In a second terminal:

```sh
sh engine/scripts/plant-standin-faults.sh     # give the checks something real to find
pnpm run prove                                # every done-test, measured, -> engine/docs/receipts/
node engine/gateway/cli.js verify-chain engine/standin/state/audit.log
sh engine/scripts/plant-standin-faults.sh --clear
```

Connect any MCP client to `http://127.0.0.1:8095/mcp` with `Authorization: Bearer <contents of seat-runner.token>`. Tokens live in 0600 files and are never printed.

## Run it on QNX 8.0 [SDP — Phase 0]

```sh
source ~/qnx800/qnxsdp-env.sh
sh scripts/phase0.sh           # records SDP + qcc -V, builds the image (runner via qcc -Vgcc_ntox86_64), surveys the target
sh image/run-qemu.sh           # QEMU x86_64, user networking, host :7781 -> guest :7781, serial log -> docs/phase0/
node gateway/server.js qnx/config.json
node scripts/prove.js qnx/config.json docs/receipts    # same proof, now on QNX
```

`image/build-image.sh` and `image/run-qemu.sh` were written before the SDP was installed. Steps marked **VERIFY** are checked against the real SDP at Phase 0. This repository ships source and build instructions only, **no QNX image or SDP files**.

## Origins

Created for this hackathon. The design descends from two of our own earlier projects. **Parrot AI** (Nov 2026) contributed the gateway ladder, scope gate, audit chain and verification loop. The **MCP3 Code Mode profile** (Nov 22, 2026) contributed the search/execute surface, the 40,000-char slice rule and fail-closed scoping. The QNX runner, inventory, checks, Qnet scope rules and this implementation are new.
