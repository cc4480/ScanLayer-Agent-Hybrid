   Obtain a TLS certificate (free from Let's Encrypt) and redirect all HTTP traffic to HTTPS. Set up HSTS once HTTPS is working.

2. [HIGH] Missing Content-Security-Policy (CSP)
   Implement a strict CSP. A starting point: Content-Security-Policy: default-src 'self'; script-src 'self'; object-src 'none'; base-uri 'self'. Tighten over time using CSP violation reports.

3. [MEDIUM] Missing Clickjacking Protection (X-Frame-Options)
   Add: X-Frame-Options: DENY (or SAMEORIGIN if you need to embed within your own domain). Alternatively use: Content-Security-Policy: frame-ancestors 'none'

4. [MEDIUM] Missing X-Content-Type-Options: nosniff
   Add to all responses: X-Content-Type-Options: nosniff

5. [INFO] Missing Referrer-Policy Header
   Add: Referrer-Policy: strict-origin-when-cross-origin (or 'no-referrer' for maximum privacy)

6. [INFO] Missing Permissions-Policy Header
   Add: Permissions-Policy: camera=(), microphone=(), geolocation=(), interest-cohort=(). Adjust based on what your app actually needs.

7. [INFO] Missing Cross-Origin-Opener-Policy (COOP)
   Add: Cross-Origin-Opener-Policy: same-origin (most secure) or same-origin-allow-popups if you need cross-origin popup interaction. Only required if you use SharedArrayBuffer or high-resolution timers.

8. [INFO] Missing Cross-Origin-Embedder-Policy (COEP)
   Add: Cross-Origin-Embedder-Policy: require-corp. Note: this requires all subresources to serve a CORP or CORS header. Use credentialless if require-corp causes third-party resource breakage.

9. [INFO] Missing Cross-Origin-Resource-Policy (CORP)
   Add: Cross-Origin-Resource-Policy: same-origin (for same-site-only resources) or same-site. Use cross-origin only for truly public resources.

10. [LOW] Permissive CORS Policy (Wildcard Origin)
   If this site serves only public content, no action is needed. For endpoints that return user-specific data, replace the wildcard with an allowlist of trusted origins: Access-Control-Allow-Origin: https://your-frontend.com.

11. [INFO] X-Powered-By Header Discloses Technology Stack
   Remove the X-Powered-By header. In Express.js: app.disable('x-powered-by'); In PHP: expose_php = Off in php.ini

12. [HIGH] Session Cookie Missing Secure Flag
   Add the Secure attribute to all session cookies: Set-Cookie: name=value; Secure; HttpOnly; SameSite=Lax

13. [MEDIUM] Session Cookie Missing HttpOnly Flag
   Add the HttpOnly attribute to all session cookies: Set-Cookie: name=value; HttpOnly; Secure; SameSite=Lax

14. [LOW] Session Cookie Missing SameSite Attribute
   Set SameSite=Lax or SameSite=Strict on all session cookies: Set-Cookie: name=value; Secure; HttpOnly; SameSite=Lax

15. [HIGH] Git Config Exposed
   Block all access to .git at the web server level.

16. [CRITICAL] Environment File Exposed (.env)
   Rotate ALL credentials in the file immediately. Block .env* files: `location ~ /\.env { deny all; }`. Never place .env files in the web root.

17. [HIGH] PHP Info Page Exposed
   Delete phpinfo.php from production. Never deploy debug scripts to production servers.

18. [CRITICAL] Backup Archive Exposed
   Remove all backup files from the web root. Store backups in a private, access-controlled location.

19. [INFO] Package Manifest Exposed (package.json)
   Block access to package.json from the web server. Ensure build artifacts are not deployed to the web root.

20. [MEDIUM] Verbose Error Pages Expose Internal Application Details
   Disable debug mode in production. Use a generic error page that reveals nothing. Log detailed errors server-side only. Framework guides: Express.js — use a production error handler middleware. Django — DEBUG = False. PHP — display_errors = Off in php.ini. Rails — config.consider_all_requests_local = false.

21. [INFO] Rate Limiting Not Advertised in Response Headers
   Confirm that rate limiting is enforced on login, registration, password reset and API endpoints — the routes that matter for brute force and credential stuffing. If it is already enforced at your CDN or load balancer, no change is needed. Returning X-RateLimit-Limit, X-RateLimit-Remaining and Retry-After makes the protection visible to clients and to scanners.

22. [MEDIUM] Directory Listing Enabled
   Disable directory listing at the web server. Nginx: remove the 'autoindex on' directive. Apache: add 'Options -Indexes' to the relevant directory block or .htaccess.

23. [CRITICAL] CORS Misconfiguration — Credentials Allowed from Arbitrary Origin
   Maintain a strict server-side allowlist of trusted origins. Never dynamically reflect the incoming Origin header without validating it against the allowlist. Never combine a dynamic origin with credentials: true.

24. [MEDIUM] Open Redirect Vulnerability
   Validate all redirect targets against an allowlist of permitted paths or domains. Prefer relative paths. If external redirects are needed, use an intermediate confirmation page and never accept destination URLs from user input directly.

25. [INFO] No Structured Data Found
   Add JSON-LD for the types that describe the page — Organization and WebSite on the homepage, Article, Product or FAQPage on content pages.

26. [INFO] Incomplete Open Graph Metadata
   Add og:title, og:description and og:image (absolute https:// URL, at least 1200×630) to the document head.

27. [LOW] JavaScript Source Map Exposed — Source File Names Only
   Disable source map generation in production builds. Webpack: set devtool: false or devtool: 'hidden-source-map' (generates maps but does not link them from the bundle). Vite: set build.sourcemap: false. If you need source maps for error tracking, upload them directly to your error tracker (Sentry, Datadog) and keep them off the public server.

28. [CRITICAL] Stripe Live Secret Key Exposed
   Immediately revoke this key in the Stripe Dashboard. Stripe secret keys must ONLY be used server-side. Use Stripe.js (publishable key) for client-side payment collection.

29. [CRITICAL] Path Traversal / Local File Inclusion (LFI)
   Never construct file system paths from user input. If file selection is required: (1) Use an allowlist of permitted file names or IDs only, (2) Resolve the final path with path.resolve() or equivalent and assert it starts within the permitted directory, (3) Never pass user-controlled values directly to file-reading APIs. Block any path containing '..', encoded variants, or null bytes at the input validation layer.

30. [HIGH] Reflected Cross-Site Scripting (XSS)
   Context-aware output encoding is the fix: HTML-encode user input before rendering it into the page (<, >, ", ', & → entities). Use your framework's auto-escaping (React/Vue/Angular escape by default — avoid dangerouslySetInnerHTML / v-html / bypassSecurityTrust). Add a strict Content-Security-Policy (script-src 'self') as defence in depth.

31. [CRITICAL] SQL Injection (Error-Based)
   Use parameterised queries / prepared statements (bound parameters) for every database call — never build SQL by string concatenation. Use your ORM's parameter binding. As defence in depth, validate/allowlist input types and run the database account with least privilege. Also disable verbose SQL error messages in production.

   No action required — this maps the tested attack surface for context.

   Optional hardening: suppress the Server / X-Powered-By response headers at the web server or reverse proxy so the stack isn't advertised.

34. [HIGH] [SecLayer] Exposed Credential Signature (AWS Access Key ID)
   Remove the credential from client code, rotate it immediately, and proxy any required third-party calls through an authenticated backend that holds the secret server-side.

35. [HIGH] [SecLayer] Weak/Predictable Security Token (resetToken)
   Generate security tokens with a cryptographically secure random source (e.g. crypto.randomBytes(32).toString('hex') in Node.js) producing at least 128 bits of entropy — never Math.random() or another non-CSPRNG source.

36. [HIGH] [SecLayer] Weak/Predictable Security Token (sessionToken)
   Generate security tokens with a cryptographically secure random source (e.g. crypto.randomBytes(32).toString('hex') in Node.js) producing at least 128 bits of entropy — never Math.random() or another non-CSPRNG source.

37. [HIGH] [SecLayer] Outdated Library Vulnerability Detected (Lodash)
   Upgrade lodash to >= 4.17.21.

38. [CRITICAL] [SecLayer] Active OS Command Injection
   Avoid invoking underlying operating system commands entirely. If required, use strictly sanitized arguments array APIs, never shell-interpolated execution.

39. [CRITICAL] [SecLayer] Active Server-Side Request Forgery (SSRF)
   Enforce strict network path isolation for backend fetches. Implement allow-listing filters and block internal Class A/B/C IP architectures.

40. [CRITICAL] [SecLayer] Active Server-Side Template Injection (SSTI)
   Never render user input as part of a template. Pass untrusted values only as data/context to a pre-compiled template, use a logic-less/sandboxed engine, and validate/allow-list any dynamic template selection.

41. [MEDIUM] [SecLayer] Host Header Injection (reflected via X-Forwarded-Host)
   Never build absolute URLs from client-supplied Host / X-Forwarded-Host headers; use a fixed canonical host. If a reverse proxy legitimately sets X-Forwarded-Host, validate it against an allow-list before trusting it.

42. [HIGH] [SecLayer] Server-Side Prototype Pollution (proven via gadget)
   Guard the merge: reject or skip the keys "__proto__", "constructor", and "prototype" when recursively merging untrusted input, or use a null-prototype target (Object.create(null)) / a Map, or a vetted merge utility that is prototype-pollution-safe. Validate request bodies against a schema so unexpected keys are dropped.

43. [HIGH] [SecLayer] Business-Logic Price Tampering (client-controlled price honored)
   Never trust a client-supplied price. Look each item's price up server-side by product id (for the requested currency/region) and compute the total from that; ignore any price/amount field in the request body. Enforce it again server-side at the payment/charge step.

44. [HIGH] [SecLayer] Webhook Signature Verification Bypass (conditional on payload)
   Verify the webhook signature UNCONDITIONALLY, before any branching on the payload (currency, event type, amount). Use the provider SDK's constructEvent/verifyHeader on the raw body for every request and reject anything that fails — never gate the check on a field taken from the untrusted body.

45. [CRITICAL] [SecLayer] Server-Side Template Injection (discovered parameter "name" on /vuln/render)
   Never render user input as a template. Pass untrusted values only as data to a pre-compiled/sandboxed template for this parameter.

46. [CRITICAL] [SecLayer] Server-Side Template Injection (discovered parameter "q" on /)
   Never render user input as a template. Pass untrusted values only as data to a pre-compiled/sandboxed template for this parameter.

47. [HIGH] [SecLayer] GraphQL Schema Introspection Exposed
   Disable introspection blocks in the production GraphQL backend. Shield API with explicit token authentication schemas.

48. [INFO] [SecLayer] OpenAPI/Swagger Spec Exposed
   If this API is internal or admin-only, stop serving the specification publicly (or require authentication for it). If it is a public API, no change is needed.
